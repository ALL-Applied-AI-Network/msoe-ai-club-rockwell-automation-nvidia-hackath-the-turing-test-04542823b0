# Project Runbook: Dataset Inventory & Operations

This document records the dataset inventory, folder structure, label formats, and instructions for running project scripts for **Dataset 2 — Fluid Mixing Station 3**.

---

## 1. Dataset Inventory

All raw files reside in `data/csi-vial-fill-dataset/` (synchronized multi-camera video and image captures of an automated liquid-dosing and vial-filling line).

### A. Camera Stations & Folders

| Station / Folder | What It Shows | Equipment & Reagents |
| :--- | :--- | :--- |
| **`cap_seal/`** | Cap & seal station | Watches vial caps being placed and sealed. |
| **`tank_level/`** | Supply reagent tanks | Monitors dosing tanks: `T100` (clear diluent), `T200` (orange dye), `T400` (blue dye). Tank `T300` was out of service. |
| **`vial_fill/`** | Vial fill station | Watches vials being filled by the dispensing nozzle. *(This is the primary labeled station).* |

### C. What the Label Files Contain

All label files are located in `data/csi-vial-fill-dataset/vial_fill/labels/`:

#### 1. `video5_vial_recipes.csv` (Per-Vial Recipe Table)
Contains ground-truth dosing recipe details for each of the 30 vials filled during Video 5:
- **Columns:**
  - `vial`: Sequential vial number (1 to 30).
  - `recipe_id`: Target recipe number (Recipes 5 through 14).
  - `type`: Recipe category (Triple mix or Pair mix).
  - `t100_ml`, `t200_ml`, `t400_ml`: Volume in milliliters drawn from each tank.
  - `total_ml`: Total fluid volume dispensed.
  - `dispense_order`: Fluid sequence (e.g., `T200>T400>T100`).
  - `color_purpose`: Human-readable description of target color.
  - `start_time`, `end_time`: Start and end times as `m:ss.s`.
  - `start_s`, `end_s`, `duration_s`: Timing in seconds.
  - `start_frame`, `end_frame`: Video frame indices at 30 fps.

**3 Example Rows:**
```csv
vial,recipe_id,type,t100_ml,t200_ml,t400_ml,total_ml,dispense_order,color_purpose,start_time,end_time,start_s,end_s,duration_s,start_frame,end_frame

```

#### 2. `video5_frame_labels.csv` (Per-Frame Image Table)
Maps the vial recipes directly to the 845 still camera frames sampled during Video 5:
- **Columns:**
  - `filename`: Image filename in `vial_fill/images/`.
  - `timestamp`: Precise camera capture timestamp (`YYYY-MM-DD HH:MM:SS.microseconds`).
  - `video_s`: Elapsed video time in seconds.
  - `in_fill`: Binary indicator:
    - `1` = Active fill (fluid is currently being dispensed into a vial).
    - `0` = Between fills (station is idle between vials).
  - `vial`, `recipe_id`, `type`, `t100_ml`, `t200_ml`, `t400_ml`, `total_ml`, `dispense_order`, `color_purpose`: Recipe metadata for active fills.

**3 Example Rows:**
```csv

```

### Activating the Python Environment
Before running any script, make sure your `.venv` virtual environment is active in PowerShell:
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
.\.venv\Scripts\Activate.ps1
```
*(You will see `(.venv)` appear on the left of your prompt).*

First time only, install the packages: `pip install -r requirements.txt`

- **Results on our data (all 30 vials aligned):**
  - **All 30 vials (overall)**:
    - **`cap_seal`**: Min signed gap: `-0.927 s`, Max signed gap: `+0.972 s`, Mean signed gap: `+0.070 s` (Max absolute gap: `0.972 s`, Mean absolute gap: `0.427 s`).

  - **Clock offset check**: Gaps are balanced on both sides of zero (`-0.927 s` to `+0.972 s`) with mean `+0.070 s`, confirming no systematic clock offset.
  - **2-second threshold check**: **0 vials failed.** Every camera has an aligned frame within 2.0 s for every vial (max absolute gap across all 30 vials is `0.972 s`).

### Script: `scripts/crop_vial.py` (Card 3 measurement patches & judging sheet)
- **Purpose:** Defines three fixed measurement patches inside the vial for Card 3 color analysis:
  1. **LOW patch** (`x: [302, 318], y: [352, 372]`): submerged in liquid for all 30 vials (even 30 mL), in front of the dark conveyor background.
  2. **HIGH patch** (`x: [302, 318], y: [268, 288]`): sits in front of the white paper backdrop below the carrier bracket, inside liquid for all 24 vials >= 60 mL (where meniscus is >= 5 px above y=268).
  3. **BASE patch** (`x: [304, 316], y: [389, 395]`): experimental patch in the colored glow of the thick glass vial bottom, just above the metal holding block and clear of screws.
  Computes the spatial median sRGB for each patch and converts it to CIELAB (D65) using `colour-science`. Automatically detects glass edges at each patch height and checks for any contact with glass walls, meniscus lines, carrier bracket, dark strip, screws, or specular glints (> 200 intensity). Also generates the clean 10×3 human eye judging sheet for visual ground-truth labeling.
- **Run command:**
  ```powershell
  python scripts/crop_vial.py
  ```
- **Generated output:**
  - `outputs/card3/crop_check.png` (5-vial visual check showing patches on vials 3, 6, 9, 15, and 28)
  - `outputs/card3/crop_check_all30.png` (5×6 contact grid of all 30 vials with patches and median Lab values)
  - `outputs/card3/judging_sheet.png` (10×3 contact grid: 1 row per recipe, 3 vials side by side, labeled only 'Vial N (Recipe R)')
  - Terminal table with glass edge positions, liquid coverage status, and median CIELAB colors for all 30 vials.

### Script: `scripts/baseline_check.py` (Card 3 Step 2: Baseline Color Verification)
- **Purpose:** Extracts liquid CIELAB color from last parked MP4 frames across LOW, HIGH, and BASE patches for all 30 vials. Computes ΔE2000 against each recipe's clean 3rd reference vial. Benchmarks performance against two answer keys:
  1. **Human judge_1** from `annotations/video5_visual_verdicts.csv` (evaluated twice: counting 'unsure' as OFF, and counting 'unsure' as FINE).
  2. **Advance Rule** (1st vial after each recipe change = at risk; all 2nd vials = fine).
  Evaluates fixed thresholds (ΔE > 2.0, ΔE > 5.0) and strict leave-one-recipe-out (LORO) threshold selection where each held-out recipe's threshold is determined solely on the remaining recipes.
- **Run command:**

## 3. Cosmos Reason (Cosmos 3 Nano Reasoner)

### Try it in the browser first (no code)
Open <https://build.nvidia.com/nvidia/cosmos3-nano-reasoner>, **Experience** tab: upload one image or `.mp4`, type the User Prompt, press **Run**. **Preview** shows the answer, **Reasoning Complete** shows its reasoning, **JSON** shows the raw response. To turn reasoning on, end the prompt with:

```text
Answer the question using the following format:

<think>
Your reasoning.
</think>

Write your final answer immediately after the </think> tag.
```

### Cosmos: start the server (on Brev, App + Cosmos lead)
The build.nvidia.com page has no hosted Python example for Cosmos 3; its **Deploy** tab shows how to run it yourself as a NIM container. Cosmos 3 Nano needs about 17 GB of GPU memory, so it runs on a Brev **L40S** instance named `fluid-cosmos` (with Start/Stop).

**What worked (Oct 20):** Nebius L40S, *VM Mode w/ Jupyter* (no launchable needed). Everything below runs in a JupyterLab terminal (Brev website → Open Notebook → File → New → Terminal), so no Brev CLI is needed on the laptop.
**Check the driver first:** run `nvidia-smi | head -4` as soon as the instance is Running. The Cosmos container needs **CUDA Version 12.9 or higher** (Nebius showed driver 580, CUDA 13.0). A Crusoe L40S had CUDA 12.7 and Cosmos crashed with "The NVIDIA driver on your system is too old"; its driver could not be upgraded, so delete such an instance and pick another provider.
**Next sessions:** Start the instance → Open Notebook → Terminal → `docker start cosmos` → wait for the ready check in step 3.

1. Open a terminal on the instance (JupyterLab terminal, or `brev shell fluid-cosmos` if you have the CLI), then check the GPU works inside Docker (first session only):
   ```bash
   nvidia-smi                                              # should list one L40S
   docker run --rm --gpus all ubuntu nvidia-smi            # should list the same GPU
   df -h ~                                                 # the model needs tens of GB free
   ```
   If the second command fails, ask the agent on the instance to install the NVIDIA Container Toolkit for Docker.
2. On the instance (first time downloads the model; later starts are quick):
   ```bash
   docker login nvcr.io          # Username: $oauthtoken   Password: your NVIDIA API key
   read -s NGC_API_KEY           # paste your NVIDIA API key, press Enter (nothing shows; keeps it out of shell history)
   export NGC_API_KEY
   export LOCAL_NIM_CACHE=~/.cache/nim
   mkdir -p "$LOCAL_NIM_CACHE"
   chmod -R a+w "$LOCAL_NIM_CACHE"
   docker run -d --name cosmos \
       --gpus all \
       --ipc host \
       --shm-size=32GB \
       -e NGC_API_KEY \
       -v "$LOCAL_NIM_CACHE:/opt/nim/.cache" \
       -u $(id -u) \
       -p 8000:8000 \
       nvcr.io/nim/nvidia/cosmos3-reasoner:latest
   docker logs -f cosmos         # watch it download and start; Ctrl+C stops watching, not the server
   ```
3. Check it is ready (second Brev terminal): `curl http://127.0.0.1:8000/v1/health/ready`. If it refuses to connect, check `docker ps -a`: "Exited" means it crashed; `docker logs cosmos 2>&1 | grep -iE "error|memory|driver"` shows why.
4. **Where to run scripts that call Cosmos:** easiest is on the instance itself: upload the script and its images in JupyterLab, `python3 -m venv ~/venv && source ~/venv/bin/activate && pip install openai python-dotenv`, and run it there (it reaches Cosmos at 127.0.0.1:8000). Download results with right-click → Download. Only if the laptop itself must reach Cosmos (e.g. a live demo), install the Brev CLI and, on the laptop, in a terminal you leave open:
   ```powershell
   brev port-forward fluid-cosmos --port 8000:8000
   ```
   (Alternative: `ssh -L 8000:localhost:8000 fluid-cosmos`.) Now `http://127.0.0.1:8000` on the laptop reaches Cosmos.
5. When finished: Stop the instance in the Brev website (or `brev stop fluid-cosmos`), wait for "Stopped", and log the hours.

## 6. CSI Session Day Operations (New-Recording Mode)

This section details how to process a new recording on site at CSI Station 3 (or from an offline run provided by CSI) without manual labeling.

### A. Folder Setup & File Placement

1. Choose a run name (e.g. `csi_oct30` or `video5_practice`).
2. Place the recorded `vial_fill` camera video and recipe sequence into `data/runs/<name>/`:
   - **Video:** `data/runs/<name>/video.mp4` (the recording from the `vial_fill` station camera).
   - **Recipe List:** `data/runs/<name>/recipes.csv` (fill order, target recipe, and tank volumes).
   *Template:* Copy and fill `annotations/run_recipes_template.csv`:
   ```csv
   vial,recipe_id,t200_ml,t400_ml,t100_ml,is_reference
   1,5,10.0,10.0,10.0,
   ```
   *(Note: Leave `is_reference` empty to auto-assign the last vial of each contiguous recipe block as the reference).*
3. *(Optional Paper Answer Key)* If a teammate scored vials by eye during dispensing, save their verdicts before launching the dashboard:
   - **File:** `outputs/runs/<name>/judge_verdicts.csv`
   - **Format:** `vial,verdict` (where `verdict` is `matches`, `unsure`, or `off`).

---

### B. The One Command to Build the Run

Run `scripts/new_run.py` to turn the raw recording and recipe list into a verified run table:

```powershell
python scripts/new_run.py --video data/runs/<name>/video.mp4 --recipes data/runs/<name>/recipes.csv --name <name>
```
*(In `.venv`: `.\.venv\Scripts\python.exe scripts/new_run.py --video data/runs/<name>/video.mp4 --recipes data/runs/<name>/recipes.csv --name <name>`)*

**What this command performs automatically:**
1. **Recipe Validation:** Validates physical station limits (≤80 mL total, ≤50 mL from T-200, no T-300, ≥2 vials per recipe) and catches column typos.
2. **Autonomous Fill Detection:** Locates every filled vial parked under the dispensing nozzle using starwheel motion gating and liquid fill color change in the LOW patch (`detect_parked_vials.py`).
3. **Count Verification:** Confirms detected vial count matches recipe count. If mismatched, lists rejected parked intervals and outputs `outputs/runs/<name>/contact_sheet.png`.
4. **Camera Alignment Check:** Runs glass-edge detection across all vials to ensure the camera was not bumped or moved.
5. **Reference Assignment:** Designates clean 3rd vials (or the last vial of each recipe) as reference baselines.
6. **Outputs Run Table:** Saves `outputs/runs/<name>/vials.csv`.

---

### C. Launch the Dashboard in Recorded Run Mode

Start the operator dashboard:

```powershell
streamlit run app/dashboard.py
```

1. In the left sidebar, change **Source** from `Video 5 (demo)` to **`Recorded run`**.
2. Select your run folder (`<name>`) from the **Select Run Folder** dropdown.

**Dashboard Features in Recorded Run Mode:**
- **Honesty Banner:** Confirms recorded run mode and names the clean reference vials taken from the recording itself.
- **Pre-Fill Recipe Queue:** Computes risk lights ($\Delta E$ gap) dynamically using the run's own clean references (`scripts/flush_advisor.py --run`).
- **Blank-Normalized Inspection:** Evaluates vials using neighbor-blank normalized transmittance ($T = \text{patch} / \text{blank}$) to stay robust against room lighting variations.
- **Lighting Warning:** Panel 2 alerts operator with a yellow warning if background lighting shifted by $\Delta E > 3.0$ relative to that recipe's reference vial.
- **Live Trial Log:** Every inspected vial is automatically appended to `outputs/runs/<name>/trial_log.csv`.
- **End-of-Run Comparison:** When the last vial is reached, displays an evaluation table comparing system verdicts against `outputs/runs/<name>/judge_verdicts.csv` (if provided).
